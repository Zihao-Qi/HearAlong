# Local context admission

HearAlong uses Pi's OpenAI-compatible streaming API for both local providers. The pinned Pi 1.3.0 implementation accepts a per-request `fetch`; it does not supply an Ollama-native `options.num_ctx` setting. We do not assume adding that field to an OpenAI request changes server context.

## Measure the loaded model, not its trained maximum

- **Ollama:** `/api/tags` supplies IDs. `/api/show`'s `model_info.*.context_length` is a trained maximum, not the context actually allocated. The provider instead reads `/api/ps`, matching `name` or `model` and taking `context_length`.
- **LM Studio:** OpenAI `/v1/models` supplies IDs, not usable context. REST `/api/v1/models` supplies `models[].key` (or `id`) and `loaded_instances[].config.context_length`. For the older REST shape, `/api/v0/models` supplies `data[].id`, `state: "loaded"`, and `loaded_context_length`. `max_context_length` is not used. If several instances report different contexts, use the smallest; an instance without a context makes it unknown.
- Catalog context metadata is cached in the Pi process for five seconds. Before **each inference POST**, the provider re-reads loaded metadata, replacing the cache if the server reports a different allocation.
- If metadata shows the selected model is not loaded, send one fixed request to the same `/v1/chat/completions` endpoint: `messages: [{role: "user", content: "Hi"}]`, `max_tokens: 1`, `stream: false`. It contains no meeting text. Allow up to five minutes for loading, matching Ollama's default load limit. Concurrent callers in one provider process share the operation, but one cancelled caller cannot cancel another caller's load; the last caller leaving cancels it.
- An Ollama `/api/ps` entry with `context_length: 0` means **still loading**. Re-read metadata at one-second intervals within the five-minute bound, rather than refusing and aborting sibling notes calls. Metadata requests retain their 1.5-second limits. Only a loaded model with unknown context receives context-setting guidance; failed loading or an expired load bound names the model and suggests checking its server.
- Recommend `qwen3.5:4b` (about 4 GB). In Ollama's settings, set the context length to 32k so a long meeting fits; on a 16 GB Mac the default can be only 4k. Unknown loaded context gives instructions to set Ollama's context length (for example 32768, in settings or `OLLAMA_CONTEXT_LENGTH`) and restart, or to set LM Studio's context length when loading the model. A one-token catalog sentinel represents **unknown**, not an inferred usable default. Unloaded models are measured inside the provider; the notes preflight does not reject that sentinel before warm-up can occur.

## Admission estimate

The estimate is **3 Unicode characters per token, plus 25%, plus 512 fixed tokens**, with the requested output allowance added separately. With thinking off, output keeps the existing allowance: the smaller of the requested limit, 4096 tokens and one quarter of the measured context (an unknown catalog sentinel cannot lower it). For Ollama notes only, thinking uses `reasoning_effort: "medium"` and an allowance of `min(16384, measured context − estimated input − 512)`. If that leaves fewer than 6144 tokens, that request falls back to thinking off and the existing allowance. Meeting text always takes priority; input is never clipped to make thinking fit. This is a deliberately padded estimate, not an exact tokenizer. The provider checks the complete serialized messages/tool declarations and the effective output limit immediately before sending the actual prompt; notes also preflight known catalog limits. No transcript is sliced, no server truncation is requested, and Pi automatic compaction is cancelled. Over-limit requests fail instead of sending a deliberately shortened prompt.

The allocation and tokenizer are controlled by the local server; the estimate is not a mathematical bound for every tokenizer or custom chat template. The first real Ollama check used Homebrew Ollama 0.40.11 (MLX), `qwen3.5:4b`, and a 32k allocation on an M2 / 16 GB Mac. It exposed cold-load cancellation, inference queue timeouts, and default thinking consuming the output allowance; these follow-up fixes are tested with loopback fakes, not a new real-model run. In particular, another client must not resize/unload the model between measurement and submission. Tests here use loopback fakes only, including a reduced loaded context and a too-long prompt that never reaches the fake inference endpoint.

## Transport and evidence

Discovery, warm-up, metadata and both Pi streaming methods use one loopback-only fetch with its own direct Undici dispatcher, independent of global/environment proxy configuration. Inference allows ten minutes for response headers and five minutes between response-body chunks; discovery and metadata keep their short abort limits. A stopped server still fails immediately. Ollama warm-up, corrections, Board, setup tests and all non-notes inference requests send `reasoning_effort: "none"`. Notes opt in explicitly through `runPiTask`'s `localNotesThinking` option, set only by the notes runner for its medium-thinking parts. The task launch sets a child-only `MEETING_LOCAL_NOTES_THINKING=1` marker; ordinary launches clear any inherited marker. The extension uses that opt-in, not Pi's stream reasoning option: Pi 1.3.0 clamps `--thinking medium` to off for our `reasoning: false` catalog, and RPC's `--thinking low` must never authorize thinking. The catalog stays unchanged. `reasoning: false` alone does not disable Qwen's default thinking, and Ollama's OpenAI API ignores `think: false`. LM Studio requests are unchanged and send no `reasoning_effort`. A local `length` stop still names the model and says it ran out of room to write its answer, suggesting a model that can finish within the output limit rather than promising shorter input will defeat the 16384 cap.

Local model work uses one server-wide lane across tasks and RPC: notes parts run sequentially, and actions, memory, plans, Board scans and corrections wait their turn. Task/RPC timers start after admission; lane waiting does not consume the notes parts' unchanged 600-second limits. Local RPC uses a ten-minute request limit, including cold loading and inference, rather than the cloud Quick/Board deadlines. Cancelling admission or closing local RPC defers Board/correction work without spending their failure budgets; cloud deadlines and task cancellation outcomes are unchanged. A local plan holds the lane for its whole job before either job deadline starts; concurrent child writers use a serial inner lane. Local RPC children exit before releasing the lane rather than keeping another Pi process warm. Cloud calls, including notes parts, remain parallel. Notes' existing per-part counts/done flags and latest streamed item remain available while parts wait. Each measured response carries only a boolean thinking flag and numeric effective allowance into the per-request `job-durations.json` notes diagnostics, alongside existing usage/stop reason. Unreported values (including a process killed before any response event) stay null; no prompt or reasoning text is added to diagnostics. All redirect responses are refused before another origin is contacted. Local Pi children additionally lose every case variant of HTTP/HTTPS/ALL/NO_PROXY. Endpoints and every individual request URL are checked.

Evidence sources available offline were Pi's `docs/custom-provider.md`, `docs/models.md`, and `pi-ai/dist/api/openai-completions.js` / `types.d.ts`. Separate Ollama/LM Studio API manuals were not installed in this checkout. The response shapes above follow the published [Ollama running-model API](https://docs.ollama.com/api/ps) and [LM Studio REST model APIs](https://lmstudio.ai/docs/developer/rest) as understood from their documented contracts; those links were **not fetched**. The initial integration was verified with fakes; the real check described above motivated this follow-up. Regression tests use fictional inputs and ephemeral loopback fake servers only. A further real-model check is still needed to verify the changes on the target Mac.
